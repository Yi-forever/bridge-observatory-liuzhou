# 3D 城市漫游重构开发计划

> 版本：v1.0 · 2026-10-20
> 目标：把「桥见柳州」从滚动式网页重构成**单一 3D 场景入口**的沉浸式城市漫游应用。
> 说明：原《VR/AR 增强开发代办清单》已废弃删除；VR/AR 能力作为后续可能性保留，不在本计划范围内。

## 背景

当前项目是文档式结构：`hero → #map → #lab → #compare → #quiz → #about`，五座桥被压成 SVG 上的坐标点，桥梁的"地理性"丢失；结构实验室与桥是两套平行状态，用户感知不到"从这座桥走到那间实验室"。

重构后的形态：打开网页即进入 3D 柳江场景，五座桥沿江分布，点击桥进入单桥场景看结构讲解；场景中另有两栋建筑——**结构实验室**（力流 / 拆解 / 荷载实验）与**档案馆**（档案展示 + 知识挑战）。

## 一、最终形态（四态 + 一个保底）

| 状态 | URL | 内容 | 落地阶段 |
|---|---|---|---|
| 总览 atlas | `#atlas` | 3D 柳江 + 地形 + 五桥 + 两栋建筑 + HUD | M1 |
| 单桥 bridge | `#bridge/<id>` | 镜头推进该桥，3D 构件拾取、说明、力流、拆解 | M2 / M3 |
| 结构实验室 lab | `#lab` | 建筑内部交互（M3 先占位，指向现有 2D 页面） | M3 |
| 档案馆 archive | `#archive` | 档案展示 + 知识挑战（M3 先占位，指向现有 2D 页面） | M3 |
| 降级浏览 browse | `#browse` | 无 WebGL / 用户主动切换时的列表视图（保底） | M0 |

桥的 id 沿用现有数据：`liujiang`、`wenhui`、`wenchang`、`baisha`、`fenghuangling`；模型类型：`girder`、`arch`、`continuous`、`cable`、`pavilion`。

## 二、范围与非目标

### 范围内（M0–M4）

- 3D 总览场景：柳江河道、江岸地形、五座桥、两栋建筑
- 五座桥的 3D 简化模型与构件交互（拾取、说明、力流、拆解）
- 实验室 / 档案馆两栋建筑与占位入口
- 降级路径（列表视图）、键盘可达、深链接、浏览器回退
- Windows 11 与 Linux 桌面的正确运行

### 暂缓（非目标，后续再议）

- **移动端一等公民**：保留思路，不作为 M0–M4 验收项；移动端可先走 `#browse`
- **时间轴**（桥逐年"生长"的动画）：排到 M4，视进度决定
- **滚动式长文科普的最终归宿**：暂不删除现有内容，M1 完成后再决定（见"待定问题"）
- **VR / AR**：本计划不含；原计划文档已丢弃

## 三、设计原则

1. **渐进增强 + 保底降级**：所有 3D 入口先做能力检测，不支持时进入 `#browse`，页面永远可用。
2. **DOM 覆盖层**：3D 物体在 canvas 里，文字与交互 UI 用 DOM——复用现有 `styles.css`、科普文案、`localStorage` 进度、深链接语义，避免把内容在 3D 里重排。
3. **单一 canvas + 状态机**：不做多页面；四态之间镜头 tween 过渡，桥模型常驻内存。
4. **URL 即状态**：`#atlas` / `#bridge/<id>` / `#lab` / `#archive`，`popstate` 可用；兼容旧 `#bridge=<id>&mode=force&explode=1`。
5. **风格化 low-poly**：契合"教学简化、非真实比例"定位，规避真实底图版权，同时压住性能。
6. **本地打包、离线可用**：Three.js 等依赖打包进仓库，禁止 CDN；断网时核心功能可用。
7. **桌面优先**：Windows 11 + Linux 桌面（Chrome / Edge / Firefox）为一等目标。
8. **始终可运行（Always Runnable）**：从 M1 起，仓库任意一次提交都必须能 `node server.js` 打开看到效果；未完成部分用**占位资产**代替，绝不出现白屏、报错、无响应或死链。进度可以慢，但"随时能演示"不能破。

## 四、技术方案

### 4.1 运行方式（硬约束，先改）

现状 `start.bat` 是 `start "" "index.html"`，走 **file:// 协议**。file:// 下 ES module、fetch、Worker、WebGL 纹理加载都会失败——**3D 必须通过 HTTP 访问**。

- [ ] `start.bat` 改为先起本地服务再打开浏览器
- [ ] 新增 `start.sh`（Linux 同等逻辑，`node server.js &` + `xdg-open`）
- [ ] `server.js` 补齐 MIME：`.mjs`、`.glb`、`.gltf`、`.bin`、`.hdr`、`.ktx2`、`.woff2`、`.wasm`
- [ ] 直接以 file:// 打开时，页面给出"请用 `node server.js` 启动"的提示，而不是白屏

### 4.2 目录结构

```text
index.html            3D 壳：canvas + HUD 层；现有滚动内容收进 #legacyRoot
app.js                现有 2D 逻辑（作为子视图保留，不删不改语义）
app3d/
  shell.css           3D 外壳样式（与 styles.css 分离）
  main.mjs            入口：能力检测、视图切换、HUD 文案
  state.mjs           状态机 + hash 路由 + popstate + 旧链接兼容
  scene.mjs           渲染器 / 相机 / 灯光 / 场景（M0 为占位舞台）
  data.mjs            桥梁数据（M0 最小副本，M1 抽共享 JSON）
  atlas.mjs           总览态：河道、地形、五桥低模、两栋建筑   [M1]
  bridge-view.mjs     单桥态：构件、力流、拆解                 [M2/M3]
  lab.mjs             实验室占位                               [M3]
  archive.mjs         档案馆占位                               [M3]
  labels.mjs          3D→屏幕投影标签                          [M1]
vendor/three/         three.module.min.js + LICENSE（版本锁定 0.180.0）
docs/
```

> 采用 `.mjs` 扩展名：项目根 `package.json` 未声明 `"type": "module"`（且 `server.js` 依赖 CommonJS），
> 用 `.mjs` 可让浏览器与 `node --check` 都按 ESM 解析，便于语法自检。`server.js` 已为 `.mjs` 提供 `text/javascript`。

### 4.3 数据与坐标映射

- 直接复用 `app.js` 的 `bridges`：`id / order / name / year / type / family / size / accent / model / deflectionBase / map / parts / tagline / observation`。
- 3D 位置由现有 `map: {x, y}`（0–100 百分比）线性映射：

```text
x3d = (map.x - 50) / 50 * W
z3d = (map.y - 50) / 50 * D
```

- 新增可选字段 `geo3d`：单桥模型尺寸、构件偏移、建筑锚点，避免污染现有 2D 数据。
- 构件数据（`parts[]`）复用，不新写文案。

### 4.4 镜头、拾取与标签

- 透视相机，FOV 45。
- **总览镜头**：45° 等距俯视；极角夹紧 35°–65°，方位角基准 ±40°，距离夹紧 60–140；**禁止自由平移**；常驻"全景复位"按钮。
- **单桥切换**：相机位置与目标点同时 tween（自写 easeInOutCubic，不引入动画库）。
- **拾取**：Raycaster，命中体比视觉模型放大 1.15 倍；hover 抬升 + 高亮。
- **标签**：手动投影（`vec.project(camera)` → 屏幕坐标 → 绝对定位 DOM），每帧更新；按距离渐隐，避免遮挡。
- **键盘**：`Tab` 在桥上循环，`Enter` 进入；`Esc` 返回上一层。

### 4.5 渲染预算

- 总览态 draw calls ≤ 150，三角面 ≤ 150k。
- 桥墩、栏杆等重复构件用实例化或合并几何。
- 阴影关闭或一次性烘焙；`renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5))`。
- 多材质合并，纹理只用程序化生成或小尺寸贴图。

### 4.6 状态与路由

```text
state.view: 'atlas' | 'bridge' | 'lab' | 'archive' | 'browse'
state.activeBridge: string | null
state.mode: 'normal' | 'force' | 'night'
state.exploded: boolean
```

- hash 变化 → 切换状态；状态变化 → 回写 hash（`history.replaceState`）。
- 旧链接兼容：解析 `#bridge=wenhui&mode=force&explode=1` 后转成 `#bridge/wenhui` 并应用 mode / explode。
- 浏览器返回键可用（`popstate`）。

### 4.7 跨平台注意事项

- **Windows 11**：`start.bat`（CRLF、`cd /d "%~dp0"`）。
- **Linux**：`start.sh`（LF 换行、`#!/usr/bin/env bash`）；`server.js` 已用 `path` 模块，跨平台无需改动。
- **文件名大小写**：Linux 区分大小写，现有资源均为小写，新增文件保持一致；`docs/` 下中文文件名需 UTF-8 保存。
- 两端都只需 Node，无 npm 依赖。

### 4.8 占位资产与"始终可运行"规范

原则 8 的落地方式。任何时刻主干都必须可运行、可截图、可演示；占位分四级，随里程碑推进逐级替换：

| 级别 | 形式 | 典型阶段 |
|---|---|---|
| L0 | 纯色几何块，无贴图 | M1 初期的桥体与建筑体块 |
| L1 | 程序化贴图（网格 / 条纹 / 噪点，代码生成，不引入图片） | M1 收尾、M3 过渡 |
| L2 | 简化低模 + 基础材质（可辨认桥型） | M2 文惠桥、M3 其余四桥 |
| L3 | 完成态（构件可交互、有高光 / 法线细节） | M2 / M4 最终 |

硬规则：

- **占位物必须可见、有名字、有颜色、可点击**——不允许"看不见的东西"充当占位。
- 未实现的入口点击后弹出"建设中"占位面板，而不是无响应。
- 占位纹理一律**程序化生成**，不引入外部图片资源（保持离线与体积优势）。
- 每个里程碑结束执行一次 `git` 提交，提交信息注明当前占位级别与未完成项。
- 任何一次提交都能直接 `node server.js` 打开；若某功能不可用，必须是"看得见的建设中"，不是白屏或控制台报错。

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| M2 发现 3D 讲结构不如 SVG 清楚 | 保留混合方案：总览 3D、讲解 2D；M2 前不铺开五桥 |

| 首屏变慢 | 3D 模块动态 import；先渲染 HUD 与加载提示 |
| 建模工作量失控 | 严格 low-poly；只建"讲得清传力"的必要构件 |
| 现有页面内容在重构中丢失 | 隐藏容器保留原 DOM，占位入口直接指向；M3 验收时逐项检查 |
| 跨平台问题（大小写、换行） | 新增文件统一小写/正斜杠；`start.sh` 用 LF |
| 沙箱/权限问题影响构建 | 受限 shell 对工作区子目录不可写时，构建产物放根目录或改用 DSH 文件工具 |
